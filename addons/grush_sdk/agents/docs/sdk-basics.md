# SDK の共通の約束

> GameRush の開発者向け文書（https://gamerush.jp/developers）から生成した写しです。SDK を上げたら入れ直してください。
> 元のページ: https://gamerush.jp/sdk#promises

<a id="promises"></a>
## 共通の約束

入力の検証・再送・通信方式の選択・プロトコル差分の吸収は GameRush 側のランタイムが持っていて、SDK が持つのは型のついた呼び出しと待ち合わせだけです。そのため、作者が SDK を更新しなくても GameRush 側の改善はそのまま既存のビルドへ届きます。

**SDK の更新が要るのは、新しい API を使いたいときだけです。**

- 例外を投げません。すべての呼び出しが結果オブジェクトを返します。GameRush の外（作者の自サイトなど）で動かした場合も `Unsupported` を返して静かに縮退します。ただし [アナリティクス](analytics.md#analytics) の呼び出しは、結果オブジェクトではなく真偽値を同期で返します。
- 起動時に `protocolVersion` を読みます。SDK が要求する版数を満たさない環境では、その機能を無効にします。例外は JavaScript 版のクラウドセーブの `fallback` で、無効にせず、渡さないときと同じ呼び出しになります。
- 知らないイベントは黙って捨てます。ランタイムが SDK より新しいことは常に起こり、`close` の `reason` のように既知のイベントへ新しい値が増えることもあります。

<a id="error-codes"></a>
### エラーコード

このページでは、エラーコードを Unity の `GRushErrorCode` の名前（`InvalidParams` など）で書きます。Godot と JavaScript の `code` は、同じ名前を小文字始まりにした文字列（`invalidParams` など）です。JavaScript の節と、JavaScript だけにあるクラウドセーブの説明では、JavaScript の書き方で書きます。

| コード | 意味 |
|---|---|
| `Unsupported` | GameRush の外で動いているか、その機能に対応する前の古い GameRush で動いている。待っても直らない |
| `Unavailable` | GameRush の中で動いているが、いまは使えない（再生中のセッションが無い・セッションが拒否された・確認用の表示の中・GameRush の側の失敗など）。一時的な失敗と同じコードで、ランキングの投稿で session が拒否されたときは、同じプレイの間に再送しても通らない。再送するときは回数を区切る |
| `Timeout` | 20 秒待っても GameRush から答えが無い。通報と共有のように GameRush がプレイヤーの操作を待つ呼び出しは、もっと長く待つ。JavaScript のクラウドセーブは 15 秒で切る |
| `RateLimited` | 回数の上限を超えた。多くは時間が経てば回復する。ランキングの session あたりの投稿の上限は、その session の間は回復しない（[呼び出しの回数の上限](sdk-basics.md#rate-limits)） |
| `SignInRequired` | ゲストではできない |
| `ConsentDeclined` | プレイヤーの設定や同意で断られた（名前とアイコンを表示する設定がオフなど） |
| `InvalidParams` | 引数や payload が規則に合わない。対象が見つからないときにも返る |
| `Internal` | GameRush から読めない答えが返った、またはほかのどれにも当たらない失敗。SDK が知らないコードもこれになる |
| `PreviewRequired` | 確認用の表示を購読せずに、他プレイヤーの公開状態を読もうとした（[確認用の表示](player-state.md#player-state-preview)）。購読すれば通る |

JavaScript には、クラウドセーブの版ずれ（`baseRevision` の不一致）を表す `conflict` もあります。部屋の `error` の `code` と `close` の `reason` は、この一覧とは別の文字列で、どの SDK でも同じ綴りのまま届きます。

<a id="rate-limits"></a>
### 呼び出しの回数の上限

GameRush は、メソッドごとに続けて呼べる回数と、1 回分が戻るまでの間隔を決めています。超えた呼び出しは GameRush のサーバへ送らずに `RateLimited` で返ります。

**毎フレーム呼ばないでください。結果を手元に持って使い回し、呼ぶのは画面を開いたときや操作したときにしてください。**

| 呼び出し | 続けて呼べる回数 | 1 回分が戻るまで |
|---|---|---|
| 自分のプレイヤー情報 | 5 回 | 1 秒 |
| ランキングの投稿・上位・自分の周り | 5 回 | 2 秒 |
| ランキングの一覧 | 2 回 | 5 秒 |
| 公開プレイヤー状態の読み取り | 5 回 | 2 秒 |
| 公開プレイヤー状態の書き込み | 3 回 | 3 秒 |
| 相手探し | 3 回 | 3 秒 |
| 受信箱の送信・一覧 | 5 回 | 2 秒 |
| 交換所の出品 | 2 回 | 5 秒 |
| アイテムの購入 | 1 回 | 5 秒 |
| 部屋への join | 3 回 | 9 秒 |
| 部屋への招待 | 1 回 | 5 秒 |
| 通報 | 2 回 | 5 秒 |
| 共有 | 1 回 | 5 秒 |

- 表に無いメソッドにも、同じ形の上限があります。
- ランキングの投稿・相手探し・受信箱の送信・交換所の書き込み・部屋への join・共有・通報には、GameRush のサーバにも別の上限があります。値はそれぞれの節に書いてあります。
- 待つ時間が分かるときは、JavaScript の結果に待ち時間 `retryAfterMs`（ミリ秒）が入ります。この表の上限で返ったときは必ず入ります。Unity と Godot の結果には入りません。

<a id="pause"></a>
### 一時停止

- GameRush は、プレイヤーが次のゲームへ送り始めたときや一覧を開いたときにゲームを止めます。エンジンを問わず、止めている間は `document.visibilityState` が `hidden` になり、`visibilitychange` が届きます。セーブはこのときに送ってください。次のゲームへ送った後のゲームはまもなく閉じられるので、時間を置いてからの保存は届かないことがあります。
- 止めている間は `Date.now()` も止まり、再開すると止めていた時間の分だけ進みます。フレームの経過時間は `requestAnimationFrame` の時刻か `performance.now()` で測ってください。こちらは止めていた時間を含みません。
